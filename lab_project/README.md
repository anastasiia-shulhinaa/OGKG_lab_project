# Найближчі сусіди методом «Розділяй та Пануй» (Делоне / Вороной)

Лабораторна робота з ОГКГ. Для заданої множини **S** із **N** точок у E²
програма знаходить **усіх найближчих сусідів** за **O(N log N)** за
допомогою стратегії «Розділяй та Пануй».

## Запуск

```bash
pip install -r requirements.txt
python app.py
```

Потрібен Python 3.8+ з `tkinter` (входить у стандартний інсталятор Python
для Windows) та `matplotlib`.

## Як користуватися

* **Ручний режим** — оберіть «Ручний», клікайте мишею у робочій області,
  щоб додати точки (до 100). Призначений для демонстрації ідеї алгоритму.
* **Випадковий режим** — оберіть «Випадковий», задайте кількість (до 10⁴)
  і натисніть «Згенерувати». Для перевірки ефективності.
* **▶ Запустити алгоритм** — будує тріангуляцію Делоне, діаграму Вороного
  та з'єднує кожну точку з її найближчим сусідом; у журналі показує час і
  емпіричну оцінку складності `t / (N·log₂N)`.
* **Шари відображення** — вмикають/вимикають точки, ребра Делоне (сірі),
  діаграму Вороного (сині), найближчих сусідів (червоні), **розділяючий
  ланцюг** головного злиття (жирний зелений) та **усі ланцюги злиттів**,
  розфарбовані за глибиною рекурсії (фіолетовий — верхні злиття з довгими
  ланцюгами, жовтий — глибокі локальні): разом вони складають усю діаграму
  Вороного й показують ієрархію «Розділяй та Пануй». Окремий шар **медіан**
  (пунктирні вертикальні лінії поділу) показує, що верхнє злиття ділить
  множину рівно навпіл за X (напр., 15 точок → 7 ліворуч / 8 праворуч);
  розділяючий ланцюг — це крива межа, що вигинається навколо цієї медіани.
* **Бенчмарк** — будує тріангуляцію для N = 1000…10000 і друкує таблицю
  часів; майже сталий стовпчик `t/(N·log₂N)` підтверджує O(N log N).
* **Очистити** — спорожнює робочу область.

## Чому через тріангуляцію Делоне (дуальний підхід)

У завданні стратегія «Р та П» описана через пряме зшивання **діаграм
Вороного** розділяючим ланцюгом. Тут реалізовано **дуальний** варіант —
тріангуляцію Делоне методом Гібаса–Столфі. Це **той самий** алгоритм «Р та
П» із тією ж складністю O(N log N), але у двоїстому просторі, що набагато
стійкіше чисельно (без «глюків» на 10⁴ точок). Відповідність повна:

| Опис у завданні (Вороной)                         | Реалізація (Делоне)                                  |
|---------------------------------------------------|------------------------------------------------------|
| поділ вертикальною лінією по медіані X            | `S[:m]`, `S[m:]` за відсортованим X (`delaunay._build`) |
| база: 2 точки → перпендикуляр; 3 → перпендикуляри | база: 2 точки → ребро; 3 → трикутник/відрізок        |
| верхній/нижній опорні відрізки                    | нижня/верхня спільні дотичні                          |
| розділяючий ланцюг (зигзаг серединних перпенд.)   | висхідне зшивання `basel` із вилученням не-Делоне ребер |
| комірка Вороного навколо точки                    | дуальна вершина = центр описаного кола трикутника     |

Діаграма Вороного будується як **дуал** готової тріангуляції
([voronoi.py](voronoi.py)): кожна трикутна грань → вершина Вороного
(центр кола), спільне ребро двох трикутників → відрізок Вороного, ребро
опуклої оболонки → промінь назовні (відсікається до робочої області).

## Чому найближчий сусід — це ребро Делоне

**Теорема.** Для кожної точки її найближчий сусід з'єднаний із нею ребром
тріангуляції Делоне. Тому достатньо для кожної вершини перебрати лише її
сусідів у тріангуляції (сумарно O(N), бо ребер ≤ 3N−6) — це і дає
**усіх найближчих сусідів** за O(N) після побудови Делоне
([nearest.py](nearest.py)).

## Оригінальність: кеш бісектрис + явний розділяючий ланцюг

Власний внесок — повертаю задачу до **прямого** формулювання Вороного
(будую розділяючий ланцюг σ явно і показую його), але прибираю його
головну ваду — крихкі float-перетини «пряма×пряма».

**Ідея.** Кожне ребро Вороного — це бісектриса пари сайтів. Точка зламу
ланцюга — перетин **двох** бісектрис `B(p,q) ∩ B(p,r)`, що **тотожний
центру описаного кола** трикутника `(p, q, r)`:

```
B(p,q) ∩ B(p,r)  ≡  circumcenter(p, q, r)
```

Тому, **кешуючи ребра як пари-породжувачі**, кожен злам рахую точно з трьох
цілих точок (без перетину прямих), а кільце quad-edge дає лише **O(1)**
кандидатів на крок. Цим **доводиться еквівалентність** прямого ланцюга й
дуального злиття Делоне: та сама O(N log N), але **точно й без «глюків»**.

Реалізація — [voronoi_chain.py](voronoi_chain.py):
* `BisectorCache` — кеш рівнянь бісектрис і вершин-центрів кіл (з лічбою
  влучань);
* перехресні ребра (`basel`) фіксуються під час злиття (вони ніколи не
  вилучаються), а ланцюг реконструюється як **дуал** до них у фінальній
  структурі — це коректно навіть тоді, коли проміжні трикутники-містки
  згодом руйнуються.

**Перевірено (юніт-тести в історії розробки):**
* `circumcenter` ≡ перетин двох бісектрис — похибка рівно **0** (точно);
* кожна ланка ланцюга збігається з реальним ребром Вороного —
  **0 розбіжностей** на 74 849 ланках із 400 тестів;
* кеш вершин: **~66 % повторного використання** (кожна внутрішня вершина
  ланцюга спільна для двох перехресних ребер → рахується один раз).

У GUI це окремий шар **«Розділяючий ланцюг»** (головне злиття — жирним) та
кнопка **анімації** `σ_out → зигзаг → σ_in`, що наочно показує, як «Р та П»
зшиває ліву й праву половини множини.

## Складність

| Етап                                  | Складність   |
|---------------------------------------|--------------|
| сортування точок за X                 | O(N log N)   |
| рекурсивний поділ + зшивання (Делоне) | O(N log N)   |
| діаграма Вороного (дуал)              | O(N)         |
| пошук усіх найближчих сусідів         | O(N)         |
| **Разом**                             | **O(N log N)** |

Точність: предикати `ccw` та `in_circle` обчислюються в **цілій**
арифметиці (довгі цілі Python), тому орієнтаційні тести **точні** — це
усуває вироджені помилки навіть на 10⁴ точок.
